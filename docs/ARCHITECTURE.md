# Architecture

TownChess has one chess core and two clients. The native UE5 client is the primary target; the browser client is
secondary. Neither client contains rules: both speak protocol v2 ([NETWORKING.md](NETWORKING.md)).

```

            │ rules.ts · game.ts (GameCore) · material.ts · position.ts · clock.ts       │
            │ openings/ (Lichess CC0) · events.ts · pgn.ts · protocol.ts (zod v2) · types │
            └──────▲───────────────────────▲───────────────────────▲──────────────────────┘
```

## Rules

- **One game core.** `GameCore` is the only implementation of game flow. The server's `GameRoom` and the browser's
  offline `LocalSession` both delegate to it. See [CHESS.md](CHESS.md).
- **Game logic never depends on rendering.**
  - `shared`, `engine`, `learning` and `server` import nothing from `client`.
  - The UE client never decides legality; it mirrors the core's state and legal moves.
  - The presenter turns authoritative state changes into animation, but animation never changes state.
- **The server is authoritative.**
  - Clients send requests: `MOVE`, `RESIGN`, `DRAW_OFFER` and so on.
  - The server answers `MOVE_ACCEPTED` or `MOVE_REJECTED`, and broadcasts `GAME_STATE_UPDATED`.
  - Clocks and results are computed only on the server.
- **The AI never blocks a game loop.** In the browser it runs in a Web Worker; on the server (and in the local core)
  it runs on worker threads (`AiPool`).
- **Learning never modifies the rules** ([LEARNING.md](LEARNING.md), [ENGINE_AGENT.md](ENGINE_AGENT.md)).

## UE5 client and rendering

The UE5 client is `ue5/TownChess`. Its status and evidence are in [ROADMAP.md](ROADMAP.md) §5b. Offline play uses
`CREATE_AI_GAME` against the local core. The core's contract (secret, no orphans, crash journal, supervision) is in
[NETWORKING.md](NETWORKING.md). `npm run bundle:core` builds `dist/core` for packaged builds, and
`ue5/tools/win/package.ps1` stages it with `node.exe` under `Content/TownChessCore`. The packaged Windows build is
not verified yet.

The UE5 benchmark lives in `ue5/TownChessBench`. Its content is generated by `Scripts/build_scene.py` and is not
committed. It runs in Proxmox VM 131, which has the RX 6650 XT passed through.

Possible later step: Pixel Streaming (Milestone 10, optional). With it:

- The browser becomes a video and input layer.
- The UE process renders on the GPU, encodes in hardware, and sends the video over WebRTC.
- The game server stays unchanged and separate from the renderer.
