# TownChess visual transformation plan

Owner directives of 2026-10-13 ("AAA visual transformation, rendering engineering, and local AI agent workforce" and
"AAA visual transformation and multi-agent development directive"). This plan is the evidence-first answer to both:
what exists, what was measured, why it looks dated, and the order of work. Live task state:
[GRAPHICS_AGENT_STATUS.md](GRAPHICS_AGENT_STATUS.md). Beta criteria: [BETA.md](BETA.md).

## 1. Current architecture and renderer (Phase 0, verified 2026-10-13)

- **The authoritative game is a native Unreal Engine 5.8 C++ client** (`ue5/TownChess`) on branch
  `feature/photorealistic-renderer` (231 commits ahead of `main`). The public `main` README still describes the earlier
  TypeScript/Three.js browser prototype; that client (`packages/client`) still plays and is the gameplay reference, but
  the Windows executable is the UE build. Draft PR #1 carries the branch.
- **Rules authority:** TypeScript GameCore (`packages/shared`, `packages/server`). The UE client holds no rules; it talks
  protocol v2 to a bundled local core (Node sidecar) or a server. Stockfish 19 runs as a separate process (league levels).
- **Build pipeline:** `ue5/tools/win/{build,setup_content,package,test_package}.ps1` on the Windows PC (ssh alias
  `townchess-win`, workspace `C:\TownChess`); the level is generated by `ue5/TownChessBench/Scripts/build_scene.py`
  (UE Python), props by Blender (`ue5/tools/blender/props.py`), textures/sounds by our generators. Packaged build:
  `C:\TownChess\builds\Development\Windows\TownChess.exe` (2026-10-06, commit ad640d1).
- **Renderer:** UE 5.8 deferred renderer on D3D12 SM6; Lumen GI and reflections with hardware ray tracing and RT shadows
  on RT-capable GPUs (`ATCGameMode::ApplyQualityPreset`), TSR (DLSS cvar set but no DLSS plugin: LIM-012), fixed
  exposure, a post volume with grading/grain/vignette. MetaHuman characters (cinematic build, 8K skin), Poly Haven CC0
  scans, our own Blender props. Details and gaps: [graphics/RENDERER_AUDIT.md](graphics/RENDERER_AUDIT.md).
- **Hardware:** RTX 4070 Ti SUPER 16 GB (driver 616.64, verified via nvidia-smi). The RX 6650 XT 8 GB is bound to
  vfio-pci for render VM 131 (stopped); the Proxmox host itself has no GPU access, so Ollama there runs on CPU.

## 3. Primary causes of the dated look

To be filled from the Phase A specialist inspections (visual director, rendering architect, hands/character,
materials) and the judge. Lead's first look: hand clipping through pieces and deformed fingers; grime as stamped blotches;
no key-light pool from the lamp; cheap large surfaces (table, room); post-processing carrying the image.

## 4. Rendering and asset strategy

Stay on Unreal Engine 5.8. The renderer is not the ceiling: Lumen HW RT, RT shadows, MetaHuman skin and Nanite are all
available; the gaps are assets (hand mesh/pose, surfaces), lighting design and material values. A migration would cost
the working client for no measured gain. Hero-asset priority follows the directive: hands/sleeve/watch, board/pieces,
opponent, table/lamp/props, room, background.

## 5. Research findings (technique -> defect -> UE 5.8 support -> how measured)

| Technique (professional reference) | Defect it addresses | UE 5.8 | Measure |
|---|---|---|---|
| Single motivated key light with soft falloff and a pool on the play area (Alan Wake 2, RE4 Remake staging) | No key, flat lighting, bald scalp brightest | Rect/spot lights with source radius, IES profiles, RT shadows | luminance map: board centre brightest region; judge lighting row |
| Contact shadows / RT shadows from small sources (TLOU2 character grounding) | Floating hands, props | RT shadows on; per-light contact shadow length | close-up: dark contact line under fingers |
| Skin: subsurface profile, detail normal, cavity/crease grime instead of stamped blotches (TLOU2, RDR2 hands) | Orange plastic skin, leopard grime | MetaHuman skin (SSS profile), our baked BC/N | close-up judge row hands; V4 |
| Layered wood/metal with roughness variation and edge wear driven by curvature/AO (RDR2 materials) | Flat wood, uniform metal, needle scratches | Material layers in our master material; Substrate optional | detail metric without grain; base-colour capture variance |
| Hand-object interaction with IK reach/grasp (first-person games' weapon/hand rigs) | Pieces fly alone, no hand contact | Control Rig / Two-Bone IK, anim montages | motion capture of a move; no clipping |
| Atmosphere: volumetric fog with light shafts only where motivated | Empty room, no depth | Exponential height fog + volumetric | judge environment row |

Sources: Epic's UE 5.8 documentation on Lumen, Virtual Shadow Maps, MetaHuman, Control Rig and Substrate
(docs.unrealengine.com / dev.epicgames.com); the specialists add the specific references they use in their reports.
No proprietary assets or code are copied; references inform technique only.

## 6. Local-agent and hardware plan (Phase 6, measured 2026-10-13)

- **Installed:** Ollama on the Proxmox host (localhost only) with `qwen2.5:7b-instruct-q4_K_M` and `qwen3:8b`; CPU only
  (12 cores, 15 GB; the RX 6650 XT is passed through to VM 131). Nothing on the Windows PC.
- **Trial:** summarise `ue5/tools/win/lock.ps1` (573-token prompt): qwen2.5-7B 42.5 s, 7.7 tok/s, correct; qwen3-8B
  111 s, 6.9 tok/s, one detail wrong ("WaitMin" described as waiting for a stale lock). Verified by the lead.
- **Tools evaluated (public repo data, not installed):** `houtini-ai/houtini-lm` (Apache-2.0, 121 stars, updated
  2026-10-10, MCP server delegating to Ollama/OpenAI-compatible endpoints) is the better fit for Claude Code;
  `tomerzipori/local-agent-toolkit` (MIT, 5 stars, last push 2026-07-11; macOS/zsh primary per the owner) is not.
- **Decision:** at ~7 tok/s on CPU, local models suit only small, offline, verifiable tasks (file summaries, checklist
  drafts, log triage). Graphics judgement, code and integration stay with Claude. Running Ollama on the RX 6650 XT would
  mean giving VM 131 the GPU for inference (or moving it to the host) - a system change that needs the owner's approval
  and costs the AMD render-test target while it runs. Installing houtini-lm into Claude Code's MCP config is likewise
  proposed, not done.
- **GPU scheduling:** the RTX 4070 Ti SUPER is the only render/measure device; builds and captures are serialized by
  `ue5/tools/win/lock.ps1`; no inference runs on it.

## 8. Performance budgets and test requirements

- 2560x1440 on the RTX 4070 Ti SUPER: >= 60 fps average (16.67 ms), 1% low >= 45; measured by `beta_checks.ps1` (smoke
  frame times) plus a presented run on the owner's display (offscreen has no present cost).
- VRAM budget: <= 12 GB at Epic (leave headroom on 16 GB); measured with nvidia-smi during the perf run.
- Every visual change: the benchmark captures (main, hands, opponent, Black seat) at identical cameras, the metrics, and
  the judge; gameplay regressions guarded by the UE autotests (cpu, drag, keys, promo, rematch, reconnect) and the
  packaged smoke; rules by `npm test` (479 with Stockfish, never lower).

## 9. Risks, dependencies, decisions for the owner

- Usage limits: concurrently running agents share one limit (two runs were cut off); specialists run in batches.
- Hand interaction animation needs C++ (anim instance/IK) and must never gate move acceptance.
- DLSS needs NVIDIA's plugin installed into UE 5.8 (owner action; LIM-012).
- Decisions: (a) give the RX 6650 XT to local inference? (b) install houtini-lm? (c) buy nothing - all assets stay free.
